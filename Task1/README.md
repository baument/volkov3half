# Лабораторная работа — вариант 5

## 1. Что требуется по заданию

Старое задание 4.3 нужно реализовать в ООП-стиле.
В проекте есть три части:

1. `Library` — библиотека классов.
2. `ConsoleApp` — демонстрационная программа с `main.cpp`.
3. `Tests` — обычные и ошибочные сценарии.

## 2. Вариант 5

### Task1
В каждой строке найти максимальное значение и заменить его на противоположное по знаку.

В этом проекте отдельно определено поведение при повторяющемся максимуме:
если одинаковый максимум встречается несколько раз в строке, знак меняется у всех его вхождений.

### Task2
Найти максимальное значение всей матрицы. После каждого столбца,
который содержит это значение хотя бы один раз, вставить один столбец нулей.

## 3. Архитектура

```text
Generator
├── RandomGenerator
├── IStreamGenerator
├── ZeroGenerator
└── ConstantGenerator

Matrix<int>

Exercise
├── Task1
└── Task2
```

`Matrix` не знает, откуда берутся числа. Она вызывает только `generator.generate()`.
`Exercise` хранит матрицу и ссылку на генератор.
`Task1` и `Task2` реализуют свой `solve()`.

## 4. Что проверяется как ошибка

В коде предусмотрены и тестируются следующие ситуации:

- размер матрицы равен нулю;
- пользователь вводит текст вместо числа;
- пользователь вводит отрицательный размер;
- выбран пункт меню вне допустимого диапазона;
- для случайных чисел задано `min > max`;
- обращение к несуществующей строке;
- обращение к несуществующему столбцу;
- попытка вставить столбец после несуществующего столбца;
- операция над пустой матрицей;
- попытка создать `Task1` с пустой матрицей;
- `INT_MIN` в Task1, который нельзя безопасно превратить в `-INT_MIN`;
- нехватка памяти при слишком большой матрице;
- неизвестное стандартное исключение;
- неизвестная непредвиденная ошибка.

## 5. Почему Library сама не печатает ошибки

По условию библиотека классов не должна быть привязана к консольному вводу-выводу.
Поэтому библиотека сообщает об ошибке через исключение:

```cpp
throw std::invalid_argument("...");
```

А `ConsoleApp` перехватывает исключение:

```cpp
catch (const std::invalid_argument& error)
{
    std::cout << error.what();
}
```

Так библиотеку можно использовать не только в консольной программе.

## 6. Почему некоторые операции сначала работают с копией

`Matrix::fill()` и `Task1::solve()` сначала изменяют временную копию.
Только если вся операция завершилась без ошибки, копия становится новым результатом.

Это значит, что при ошибке объект не остаётся в состоянии «изменена только половина матрицы».

## 7. Сборка

```bash
cmake -S . -B build
cmake --build build
ctest --test-dir build --output-on-failure
```

```bash
./build/ConsoleApp
```

Запуск тестов напрямую:

```bash
./build/Tests
```
